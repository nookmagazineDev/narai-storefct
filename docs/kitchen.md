# เมนูครัวกลาง

หกหน้าใต้เมนู **ครัวกลาง (Kitchen)** ในแอป storefct

> เลิกใช้แล้ว: **สั่งผลิต** (`/kitchen/produce`) และ **รายการสูตรการผลิต** (`/kitchen/recipes`) — ข้อมูลอยู่ในแพลนผลิตหมดแล้ว
> ลิงก์เก่าพาไป `/kitchen/plan` · หัวข้อของสองหน้านี้ข้างล่างเก็บไว้เป็นประวัติการออกแบบ

| หน้า | path | ทำอะไร |
|---|---|---|
| แพลนผลิต | `/kitchen/plan` | ปฏิทินรายเดือน ตั้งแผนผลิตรายวัน (ทีละวัน หรือหลายวันพร้อมกัน) แล้วสร้างคำสั่งผลิตจากแผน — ดูหัวข้อ "แพลนผลิต" |
| สถานะการผลิต | `/kitchen/status` | คำสั่งผลิตที่ออกไปแล้ว กรองตามสถานะ (ค่าเริ่มต้น "ยังไม่เสร็จ") · คอลัมน์จำนวนสูตร / ควรได้ตามสูตร / ผลิตได้ / ต้นทุนตามสูตร (ต้นทุนสูตร QC/RD) / ต้นทุนผลิตจริง (ใบเบิก × ราคาตอนเบิก — `material_cost` ของ `getProductionOrders`) ทั้งรวมและต่อหน่วย · ดินสอกรอกยอดใช้จริง/จำนวนที่ได้ · ปุ่มผลิตเสร็จปิดงาน |
| รายการที่สาขาเบิก | `/kitchen/orders` | ของที่สาขาสั่งเบิก (ของที่ต้องทำ) · สั่งผลิตรายตัว หรือสร้างคำสั่งผลิตจากยอดสาขาทีเดียว · เดิมมีแท็บสถานะการผลิตด้วย ตอนนี้แยกเป็นเมนูของตัวเองแล้ว (ลิงก์ `?tab=production` เก่าพาไป `/kitchen/status`) |
| เบิกวัตถุดิบ | `/kitchen/issue` | **เบิกตามแพลน** (ค่าเริ่มต้น) คำนวณวัตถุดิบจากแพลนผลิตแล้วส่งใบเบิกไปคลังกลาง — ดูหัวข้อ "เบิกตามแพลน" · **เบิกออก** ไปใช้ผลิต · **รับเข้า** เมื่อของมาถึงครัว |
| วัตถุดิบคงเหลือ | `/kitchen/balance` | คงเหลือของครัวกลาง คำนวณสดจากเหตุการณ์ · ดินสอท้ายแถว = แก้ยอดคงเหลือ โดยบันทึกเป็นยอดนับใหม่ของสาขาครัว (`saveKitchenCount` → `dbo.stock_count` + `stock_balance` ของ `KITCHEN_BRANCH`) เลือกได้ว่าเป็นยอด ณ สิ้นวันไหน · ป๊อปอัพเดียวกันแสดงประวัติยอดนับ 30 ครั้งล่าสุด (`getKitchenCountHistory` รวมที่นับจากหน้านับสต๊อกของสาขา) พร้อมผู้บันทึกและยอดที่เปลี่ยนจากครั้งก่อน · กดช่องนับล่าสุด/ดินสอ/ไอคอนประวัติ เปิดป๊อปอัพเดียวกัน · กดชื่อวัตถุดิบ = **สต๊อกการ์ด** (`getKitchenStockCard`): ยอดยกมา + เดินยอดรายวัน รับเข้า/เบิกใช้ (สูญเสีย)/ผลิตได้/ยอดนับ → คงเหลือสิ้นวัน กดวันดูเอกสาร · ปุ่มลัด วันนี้/สัปดาห์นี้/เดือนนี้/เดือนที่แล้ว (แสดงถึงวันนี้เท่านั้น) · ปุ่ม **นำเข้ายอดนับจาก Excel** (`components/kitchen/CountImport.jsx`): ไฟล์ที่มีคอลัมน์ CODE/รหัส + จำนวน (เช่น Ending_Stock_FCT_30-09-2569.xlsx) วันที่เดาจากหัวไฟล์/ชื่อไฟล์ (พ.ศ.) ตรวจรหัสกับทะเบียนสินค้าก่อน แล้ว `saveKitchenCounts` บันทึกเป็นยอดนับ ณ สิ้นวันทั้งไฟล์ใน transaction เดียว (นำเข้าซ้ำวันเดิม = ทับ) · วัตถุดิบที่มียอดนับที่สาขาครัวขึ้นในรายการนี้ด้วย แม้ไม่อยู่ในสูตร/ใบเบิก |
| ดูรายงานการผลิต | `/kitchen/report` | ผลิตอะไรไปเท่าไหร่ เสียเท่าไหร่ ต้นทุนวัตถุดิบเท่าไหร่ ในช่วงที่เลือก · ปุ่มตาในรายการผลิต = ยอดวัตถุดิบของครั้งนั้น ตามสูตร QC/RD เทียบใช้จริง (ใบเบิกของคำสั่ง) และสูญเสีย · กดแถวสรุปต่อสินค้า = ค่าเฉลี่ยต่อครั้ง หรือต่อ 1 สูตร (เฉลี่ยจากครั้งที่มีใบเบิก) — `src/services/kitchenUsage.js` · คอลัมน์ **จำนวนสูตร** และ **ต้นทุนตามสูตร** (รวม/ต่อหน่วย จาก cost ของเมนู QC/RD) ทั้งตารางสรุปและรายครั้ง จำนวนสูตรของครั้งหนึ่ง = จำนวนสูตรของคำสั่ง × สัดส่วนที่ผลิตได้ · ต้นทุนจริงต่อหน่วยสีแดง = แพงกว่าสูตร เขียว = ไม่เกิน |
| เมนูครัวกลาง | `/kitchen/menus` | เมนู FC ทั้งหมดจาก QC/RD เรียงตามรหัส · กดเมนู = ดูสูตร (ใส่จำนวนสูตรเพื่อคูณยอดได้ · ตารางเดียวกับปุ่มเช็คสูตรของแพลนผลิต `components/kitchen/RecipeView.jsx`) · สวิตช์ = เปิด/ปิดการแสดงในหน้าครัวกลาง ใช้ร่วมกันทุกคน (`getKitchenMenuSettings` / `setKitchenMenuHidden` → `dbo.kitchen_menu_setting` สร้างด้วย `docs/migrate-kitchen-menu-setting.sql` = `office-server/sql/kitchen-005-menu-setting.sql`) · เมนูที่ปิดไม่ขึ้นในตัวเลือกเมนูของแพลนผลิต แต่แผน/คำสั่งเดิมยังอยู่ · ไม่แตะทะเบียน QC/RD |

**ปุ่มวันที่ลัด** — ทุกช่องวันที่ของเมนูครัวกลางมีปุ่มลัดข้างช่อง (`components/kitchen/DateQuick.jsx`, ช่วงคิดใน `services/dateQuick.js`):
ช่วงวันที่ = วันนี้ / พรุ่งนี้ / สัปดาห์นี้ (จันทร์–อาทิตย์) / เดือนนี้ (วันที่ 1–สิ้นเดือน) · วันเดียว = วันนี้ / พรุ่งนี้ (หรือเมื่อวาน ในช่องที่เป็นยอดย้อนหลัง เช่น ยอดนับ วันที่ผลิต) ·
หน้ารายงานการผลิตกับสต๊อกการ์ดใช้ วันนี้/สัปดาห์นี้/เดือนนี้/เดือนที่แล้ว เพราะดูข้อมูลที่เกิดแล้ว · ปุ่มที่ตรงกับช่วงปัจจุบันจะไฮไลต์สีฟ้า

## ครัวกลางคือ "สาขา" หนึ่งในระบบเดิม

ตัดสินใจไว้ว่าของที่ผลิตเสร็จจะเข้าสต๊อกครัวกลาง แล้วสาขาเบิกผ่านระบบใบเบิกเดิม
ครัวกลางจึงไม่ใช่ระบบแยก แต่เป็นสาขาหนึ่งที่มีรหัสของตัวเอง ผลที่ตามมา:

- **วัตถุดิบและสินค้าที่ผลิต ใช้ `dbo.stock_item` ชุดเดียวกับสาขา** ไม่มี master ซ้อน
  รหัสสินค้าเทียบกันได้ตรงๆ ทั้งระบบด้วย `item_key` ที่ normalize แล้ว
- **ครัวกลางรับวัตถุดิบผ่านใบเบิกเดิม** (`store_fulfillment` / `store_receiving`)
  ไม่มีตาราง "รับวัตถุดิบเข้า" ของครัวกลางเอง เพราะซ้ำกับของที่มีอยู่แล้ว
- **ครัวกลางนับสต๊อกผ่านหน้านับสต๊อกเดิม** ลงที่ `dbo.stock_count` เหมือนทุกสาขา

## สูตรตั้งต้นจากเมนู QC/RD (naraipizzeria)

หน้า **รายการสูตรการผลิต** มีปุ่ม **"ดึงจากเมนู QC/RD"** — เลือกเมนูจากทะเบียนเมนูของ naraipizzeria
แล้วได้ทั้งชื่อเมนูและสูตร (BOM) มาเติมในฟอร์มสูตรของครัว ตรวจแล้วกดบันทึกเหมือนสูตรที่กรอกเอง

- **อ่านจาก SQL ของ QC/RD** (`dbo.qcrd_menu` / `dbo.qcrd_bom` / `dbo.stock_item` ในฐาน InventoryNarai)
  ผ่าน host API ของ naraipizzeria (`GET /qcrd/menu`, `/qcrd/bom`, `/qcrd/item` ที่ `QCRD_API_BASE`
  ค่าเริ่มต้น `https://api.khanoykorshabu.com`) ทางอ่านไม่ต้องมีกุญแจ ตัวอ่านอยู่ที่ `lib/qcrdMenu.js`
  แคชไว้ 5 นาที (ปุ่ม "โหลดใหม่" ข้ามแคช)
- **ชีทต้นทุนเมนู (`1v8WRT…`) เป็นแค่ทางถอย** — naraipizzeria ตั้ง `QCRD_SOURCE=sql` ตั้งแต่ 9 ก.ย. 2026
  แล้วเลิกเขียนลงชีท ชีทจึงค้างที่ของเก่า (ตอนยังอ่านชีทอยู่ หน้าสั่งผลิตเห็นเมนู FC ที่มีสูตรแค่ 7 ตัว)
  ถ้าอ่าน SQL ไม่ได้ ระบบถอยไปอ่านชีทแล้วขึ้นแถบเตือนสีเหลืองเหนือรายการเมนู ตั้ง `QCRD_SOURCE=sheet` บังคับอ่านชีทได้
- **ไม่ได้ก๊อปทั้งทะเบียนมาเก็บ** — เมนูมีหลายพันรายการ ส่วนที่ครัวผลิตจริงมีไม่กี่ตัว
  เลือกทีละเมนู ของที่บันทึกลง `kitchen_recipe` คือสูตรที่ครัวใช้จริงเท่านั้น
- **แปลงหน่วยให้**: QC/RD เก็บยอดใช้เป็นหน่วยเล็ก (กรัม/มล.) แต่ครัวเบิกและคิดคงเหลือเป็นหน่วยสต๊อก
  จึงหารด้วยตัวแปลงหน่วยของชีท (ว่าง = 1000 เหมือนที่ QC/RD คิดต้นทุน) หน้าจอโชว์ทั้งสองตัวเลข
  และเก็บยอดเดิมไว้ในหมายเหตุของแต่ละบรรทัด (`QC/RD 15,000 กรัม`)
- **"ครัวผลิตครั้งละกี่สูตร"** คูณทั้งผลผลิตและวัตถุดิบ — ตารางครัวเก็บทศนิยม 3 ตำแหน่ง ของที่น้อย
  กว่า 0.001 หน่วยสต๊อก (เช่นเกลือ 0.3 กรัมต่อจาน) จะถูกตัดออกและขึ้นเตือน เพิ่มจำนวนสูตรเพื่อให้ติดมา
- รายการที่ติ๊ก **"ไม่ตัด BOM"** ใน QC/RD ถูกข้ามโดยค่าเริ่มต้น (ปิดได้)
- รหัสสินค้าที่ผลิต = รหัสเมนู QC/RD ซึ่งไม่ได้อยู่ใน `stock_item` ถ้ารหัสไปชนวัตถุดิบที่ชื่อไม่ตรงกัน
  ฟอร์มจะเตือน เพราะยอดผลิตจะไปบวกคงเหลือของวัตถุดิบตัวนั้น

## เบิกตามแพลน (ใบเบิกวัตถุดิบไปคลังกลาง)

แท็บแรกของหน้าเบิกวัตถุดิบ (`src/components/kitchen/PlanRequisition.jsx`)

1. เลือก **ช่วงวันที่ของแพลน** (ค่าเริ่มต้น พรุ่งนี้) และ **วันที่ต้องการของ** (ค่าเริ่มต้น วันนี้ — เป็น `Ord_DelDate` ของใบเบิก)
   นับเฉพาะแพลนที่วันที่อยู่ในช่วง ไม่นับแพลนที่คำสั่งผลิตเสร็จแล้ว ติ๊กออกรายแพลนได้
2. จำนวนสูตรของแต่ละแพลน = ยอดแผน ÷ ผลผลิตต่อสูตร (กติกาเดียวกับหน้าแพลน/สถานะการผลิต) แล้วคูณสูตร BOM ของ QC/RD
   แปลงเป็นหน่วยสต๊อกด้วยตัวแปลงหน่วยของสูตร ข้ามรายการ "ไม่ตัด BOM" รวมเป็นรายการต่อวัตถุดิบ
   ต่อท้ายชื่อด้วยเมนูที่ใช้และจำนวนสูตร
3. **ตามสูตร** ดูอย่างเดียว · **เบิกจริง** เริ่มจากตามสูตรปัดตามหน่วยเบิก (`stock_item.request_unit`) กฎเดียวกับสาขา
   (เศษเกิน 30% ของหน่วยปัดขึ้น ไม่เกินปัดลง — ของน้อย ๆ จึงปัดเป็น 0 ได้ ขึ้นป้ายเตือน) แล้วแก้ได้
4. **ส่งใบเบิก** → `POST /api/kitchen_requisition` → `/api/insert_order` ของ Narai-branch ในนามสาขาครัวกลาง
   (outlet 950 · ฐาน `myfbdatafct`) ลง `myfbdata.orderd` + `invoice` ประเภท TRF ชุดเดียวกับปุ่ม "สั่งของ" ของสาขา
   สโตร์เห็นในหน้าจัดของเหมือนใบเบิกของสาขา · ป๊อปอัพยืนยันเตือนถ้าวันส่งของนั้นครัวส่งใบไปแล้ว
   (`GET /api/kitchen_requisition?deldate=` อ่าน orderd ของ outlet 950) แต่ส่งซ้ำได้เหมือนสาขา

5. **รับจริง** (คอลัมน์ต่อจากเบิกจริง) — ยอดที่คลังจ่ายตามใบเบิกที่ครัวส่งของวันส่งของนั้น
   `GET /api/kitchen_requisition?deldate=` คืนใบที่ส่ง + รายการที่สั่ง (`orderd` ของ outlet 950) และยอดรับจริงจาก
   `/api/withdrawals` ของ Narai-branch (ตัวเดียวกับปุ่ม "โหลดต้นทุนจากใบเบิก" ของหน้าต้นทุน → `myfbdata.trans`
   TRF/RCV ถึง outlet 950) กรองเฉพาะใบที่ `Trn_InvNo` = `Ord_No` (ตรวจกับใบจริงแล้วว่าเลขตรงกัน) ค้น ±7 วันรอบวันส่งของ
   เทียบกับ **ยอดในใบ** ไม่ใช่ช่องเบิกจริงบนหน้าจอ: ตรงใบ ✓ · ไม่ตรงใบ (บอกยอดใบและผลต่าง) · ไม่ได้รับ (ใบจ่ายแล้วแต่ไม่มีรายการนี้) ·
   รอรับ (ใบยังไม่จ่าย) · **รายการเพิ่มมา** (คลังจ่ายมาแต่ไม่มีในใบเบิก) ต่อท้ายตาราง พร้อมแถบสรุปเหนือตาราง
   รายการที่อยู่ในใบแต่ไม่อยู่ในแพลนที่เลือกตอนนี้ก็ต่อท้ายตารางเหมือนกัน
   · กดเลขใบในแถบสรุป (#2636) → ป๊อปอัพเทียบยอดเบิก (ในใบ) กับยอดรับจริง **เฉพาะใบนั้น** พร้อมสถานะรายบรรทัดและมูลค่าที่รับ · ดึงยอดรับไม่ได้ = ขึ้นเหตุผลในแถบสรุป รายการใบเบิกยังใช้ได้
6. **พิมพ์รายการเบิก** (แถบล่าง) เลือกได้สองแบบ:
   - **PDF (A4)** — `printRequisitionPdf` วางใบเบิกลง iframe ที่ซ่อนไว้แล้วเปิดหน้าต่างพิมพ์ของเบราว์เซอร์
     (เลือก "บันทึกเป็น PDF" หรือสั่งพิมพ์ตรง) · `@page A4 portrait` หัวตารางซ้ำทุกหน้า แถวไม่ขาดกลางหน้า
     ชีทสรุปแพลนขึ้นหน้าใหม่ · ไม่ใช้ไลบรารี PDF เพราะต้องฝังฟอนต์ไทยและตัดคำไทยเองไม่ได้
   - **ไฟล์ Excel** → `ใบเบิกวัตถุดิบ_FCT_<วันส่งของ>[_<เลขที่ใบ>].xlsx` (`src/services/kitchenExport.js`)

## หน้าสั่งผลิต (ผลิตตามสูตร BOM)

ผลิตเป็นสองจังหวะ ฟอร์มตัวเดียวกัน (`src/components/kitchen/RecipeRunForm.jsx`):

**1. สั่ง + เบิก — หน้าสั่งผลิต** เลือกเมนูจาก QC/RD (เฉพาะเมนูที่ชื่อขึ้นต้นด้วย "FC" ซึ่งเป็นของที่ครัวกลางผลิต เช่น FCผักโขมผัดสำเร็จ
— กติกาเดียวกับแผงรายการที่สาขาเบิก คือ `isKitchenItemName` ใน `lib/kitchenRequests.js`) หน้าจอแสดงสูตร BOM
คูณตามจำนวนสูตร มีช่อง **ใช้จริง** ต่อวัตถุดิบ (หน่วยเดียวกับสูตร เช่น กรัม เพราะคนครัวชั่งเป็นหน่วยนั้น)
พร้อมผลต่างจากสูตร กด "สั่งผลิต" แล้วบันทึกตามลำดับ:

1. คำสั่งผลิต (`createManualOrder` → `saveProductionOrder` จำนวนสั่ง = ผลผลิตตามสูตร · กดสั่งแต่ละครั้งได้ใบใหม่)
2. ใบเบิกวัตถุดิบผูกกับคำสั่ง (`saveMaterialIssue`) — ยอดใช้จริงแปลงเป็นหน่วยสต๊อก เก็บยอดตามสูตร/ใช้จริงไว้ในหมายเหตุบรรทัด
3. เลื่อนเป็น **กำลังผลิต** (`updateProductionOrderStatus`)

ไม่มีช่องจำนวนที่ได้ตอนสั่ง เพราะถ้าบันทึกยอดได้ครบตั้งแต่ตอนสั่ง office-server จะเลื่อนคำสั่งเป็น
"ผลิตเสร็จ" ให้เอง คำสั่งจะไม่เคยโผล่ในงานที่กำลังทำ (หน้าสถานะการผลิตเปิดที่ "ยังไม่เสร็จ")

**2. บันทึกผล — ดินสอในหน้าสถานะการผลิต** (หัวข้อถัดไป) ผลิตเสร็จแล้วกรอกจำนวนที่ได้จริง / ของเสีย
ใบที่เบิกวัตถุดิบตอนสั่งไปแล้วจะติ๊ก "ไม่ลงใบเบิกวัตถุดิบรอบนี้" ไว้ให้ ไม่เบิกซ้ำ บันทึกตามลำดับ:

1. แก้วันที่/จำนวนสั่ง (`saveProductionOrder` แบบแก้) — เฉพาะเมื่อเปลี่ยน
2. ใบเบิกวัตถุดิบเพิ่ม (`saveMaterialIssue`) — เฉพาะเมื่อเอาติ๊กไม่ลงใบเบิกออก
3. บันทึกผลิตได้ (`saveProductionRun`) — ได้ครบตามสั่ง office-server เลื่อนเป็น "ผลิตเสร็จ" ให้เอง
4. ปิดงานเป็น "ผลิตเสร็จ" ถ้าติ๊ก (ใช้เมื่อได้น้อยกว่าที่สั่งแต่จบงานแล้ว)

office-server ไม่มี action ที่ทำทั้งหมดใน transaction เดียว หน้าเว็บจึงจำว่าขั้นไหนผ่านแล้ว
ถ้าขั้นหลังพลาด กดซ้ำจะทำต่อเฉพาะขั้นที่เหลือ ไม่ออกคำสั่งผลิตหรือใบเบิกซ้ำ
รายการ "ไม่ตัด BOM" แสดงไว้ให้เห็นแต่ไม่ลงใบเบิก

ปุ่ม "สั่งผลิต" รายตัวในหน้ารายการที่สาขาเบิกก็เริ่มคำสั่งที่ "กำลังผลิต" เหมือนกัน ส่วนปุ่มสร้างทีละหลายใบ
(สร้างจากยอดสาขา / สร้างจากแผน) ยังออกเป็น "รอผลิต" ตามเดิม

### ปุ่ม "ผลิตเสร็จ" (ปิดงาน)

dropdown สถานะในตารางเลือกได้แค่ รอผลิต / กำลังผลิต / ยกเลิก — ปิดงานต้องผ่านปุ่ม **ผลิตเสร็จ** ท้ายแถว
ซึ่งเด้งหน้าต่าง "ปิดงานผลิต" ให้กรอกยอดที่ผลิตได้ก่อน (ตั้งต้นเป็นส่วนที่ยังขาด) ไม่งั้นคอลัมน์ "ผลิตแล้ว"
จะค้างเป็น 0 ทั้งที่งานเสร็จ บันทึกแล้วยอดเข้าคอลัมน์ผลิตแล้ว (`saveProductionRun`) และปิดงานเป็นผลิตเสร็จ
(`updateProductionOrderStatus`) แม้ได้น้อยกว่าที่สั่ง ใบที่เคยบันทึกยอดแล้วเว้นช่องว่างเพื่อปิดงานอย่างเดียวได้
ถ้าบันทึกยอดผ่านแต่ปิดงานพลาด กดซ้ำจะปิดงานอย่างเดียว ไม่บันทึกยอดซ้ำ

ใบที่ผลิตเสร็จแล้วปุ่มนี้กดไม่ได้ ถ้าต้องเปิดงานใหม่ให้เปลี่ยน dropdown กลับเป็นกำลังผลิต

### ปุ่มดินสอในหน้าสถานะการผลิต

เปิดฟอร์มเดียวกับหน้าสั่งผลิต (`src/components/kitchen/RecipeRunForm.jsx`) ผูกกับคำสั่งผลิตเดิม:
สูตร BOM ตั้งต้นตามจำนวนสั่ง (จำนวนสูตร = จำนวนสั่ง ÷ ผลผลิตต่อสูตร) ช่องได้จริงตั้งต้นเป็นส่วนที่ยังขาด
แก้วันที่/จำนวนสั่งได้ (บันทึกเฉพาะเมื่อเปลี่ยน) ไม่ปิดงานให้เองถ้าไม่ติ๊ก และถ้าคำสั่งนี้เคยเบิกวัตถุดิบแล้ว
จะติ๊ก "ไม่ลงใบเบิกวัตถุดิบรอบนี้" ไว้ให้ก่อน กันเบิกซ้ำ สินค้าที่ไม่มีสูตรใน QC/RD ยังแก้จำนวนและบันทึกยอดได้

ป้าย "ไม่มีสูตร" ขึ้นเมื่อสินค้าไม่มีทั้งสูตรครัว (`kitchen_recipe`) และสูตร BOM ใน QC/RD
(`has_recipe` ของ office-server ดูแค่ตารางแรก จึงเคยขึ้นกับคำสั่งที่ออกจากหน้าสั่งผลิตทั้งที่มีสูตร)

### ยอดสูญเสียและต้นทุนวัตถุดิบ (ฟอร์มผลิตตามสูตร)

ตาราง BOM มีช่อง **สูญเสีย** ต่อวัตถุดิบ (หน่วยเดียวกับสูตร) แยกจาก **ใช้จริง**
- **ลงใบเบิก = ใช้จริง + สูญเสีย** — ของที่เสียก็ออกจากสต๊อกเหมือนกัน หมายเหตุบรรทัดใบเบิกเก็บแยกไว้
  `ใช้จริง 8,000 มล. + สูญเสีย 200 มล. (สูตร 8,000)` · ใบเบิกเก็บยอดรวมหน่วยสต๊อก (ปัด 3 ตำแหน่ง)
  ส่วนที่เป็นของสูญเสีย (`loss_qty`) และราคา ณ ตอนเบิก (`unit_price` — office-server เติมเองจาก `stock_item.price`)
- **ต้นทุน = (ใช้จริง + สูญเสีย) ในหน่วยสต๊อก × ราคาต่อหน่วยสต๊อก** จาก `stock_item.price` (ราคาคอลัมน์ C
  ของชีท item ฝ่ายจัดซื้อ) — ราคาว่างหรือ 0 = "ไม่มีราคา" ไม่รวมในต้นทุนและขึ้นเตือน · บรรทัดที่ลงใบเบิกคิดจากยอดที่ปัดแล้ว
  (ตัวเดียวกับที่ใบเบิกเก็บ ตัวเลขจึงตรงกับรายงานทุกสตางค์) · รายการ "ไม่ตัด BOM" คิดต้นทุนในฟอร์มด้วย
  แต่ไม่ขึ้นในรายงาน (ไม่ได้ลงใบเบิก) ใต้ตารางสรุป ต้นทุนใช้ / สูญเสีย / รวม
- **ต้นทุนเฉลี่ยต่อหน่วย** — ดินสอ (บันทึกผล): ต้นทุนรวมของคำสั่ง ÷ จำนวนที่ผลิตได้ทั้งหมด (รอบก่อน + รอบนี้)
  · หน้าสั่งผลิต: ÷ จำนวนที่ควรได้ตามสูตร (ยังไม่มีจำนวนที่ได้จริง)
- คำสั่งที่เบิกวัตถุดิบไปแล้ว ดินสอดึงใบเบิกเดิมของคำสั่งนั้นมาแสดงในตาราง ("เบิกแล้ว") และรวมในต้นทุนให้เอง
  (`getMaterialIssues` ช่วงรอบวันผลิตแล้วกรองด้วย `order_id`) มาบันทึกผลแค่ใส่จำนวนที่ได้ก็เห็นต้นทุนต่อหน่วย
  ส่วนที่เบิกแล้วคิดด้วยราคา ณ ตอนเบิก (`unit_price`) ส่วนของรอบนี้คิดด้วยราคาปัจจุบัน
  เบิกเพิ่มได้โดยเอาติ๊ก "ไม่ลงใบเบิกวัตถุดิบรอบนี้" ออก ช่องรอบนี้ตั้งต้นที่ 0 (ใส่เฉพาะยอดที่ใช้เพิ่ม)
- กดบันทึกผลแล้ว ต้นทุนที่เห็นตอนนั้นต่อท้ายหมายเหตุของการผลิตรอบนั้นด้วย
  (`ต้นทุนวัตถุดิบ ฿1,997.60 · เฉลี่ย ฿1,051.37/กก.`)

### ต้นทุนในหน้ารายงานการผลิต

office-server (`getProductionReport`) คิดตอนเปิดรายงาน ไม่ได้เก็บต้นทุนไว้ที่ `kitchen_production_run`
เพราะเบิกเพิ่มหลังบันทึกผลิตได้:

```
ต้นทุนของคำสั่ง  = Σ ใบเบิกทุกใบของคำสั่ง (qty × unit_price)     ← รวมของสูญเสีย
ต้นทุนของครั้งนั้น = ต้นทุนของคำสั่ง × ผลิตได้ครั้งนั้น ÷ ผลิตได้ทั้งคำสั่ง   ← ทุกครั้งของคำสั่งเดียวกันได้ต่อหน่วยเท่ากัน
สูญเสีย        = Σ loss_qty × unit_price (แบ่งแบบเดียวกัน)
ต่อหน่วยของสินค้า = ต้นทุนรวม ÷ จำนวนที่ผลิตเฉพาะครั้งที่มีต้นทุน
```

- การ์ด **ต้นทุนวัตถุดิบรวม** (บอกส่วนที่มาจากของสูญเสีย) · ตารางสรุปต่อสินค้ามี **ต้นทุนวัตถุดิบ** กับ
  **ต้นทุนเฉลี่ย/หน่วย** · ตารางทีละครั้งมี **ต้นทุนวัตถุดิบ** กับ **ต้นทุน/หน่วย**
- ไม่มีต้นทุน: ผลิตนอกคำสั่ง · คำสั่งที่ไม่มีใบเบิก ("ไม่มีใบเบิก") · ใบเบิกไม่มีราคาเลยสักบรรทัด ("ไม่มีราคา")
  — ครั้งพวกนี้ไม่ถูกนับในตัวหารของต้นทุนเฉลี่ย (ตารางสรุปบอกว่า "ไม่มีต้นทุน N ครั้ง")
- บางบรรทัดในใบเบิกไม่มีราคา = ต้นทุนต่ำกว่าจริง ขึ้น "ไม่มีราคา N รายการ" / "ราคาไม่ครบ N ครั้ง" — เติมราคาในชีท item
  แล้วใบเบิกใหม่จะมีราคา (ใบเก่าไม่เปลี่ยน)
- ราคาเก็บ ณ ตอนเบิก ราคาในชีทเปลี่ยนทีหลังไม่ย้อนไปเปลี่ยนต้นทุนที่ผลิตไปแล้ว · ใบเบิกที่มีก่อนเพิ่มคอลัมน์
  ได้ราคา ณ วันที่รัน migration (ครั้งเดียว) · ของสูญเสียในใบเก่าไม่ได้แยกไว้ จึงนับเป็นยอดใช้ทั้งหมด
- ต้องมีคอลัมน์ `unit_price` / `loss_qty` ก่อน: คลิกขวา `office-server\update-office-server.bat` ของ repo
  **Narai-branch** → Run as administrator (รัน `office-server/sql/kitchen-003-issue-cost.sql` — ตัวเดียวกับ
  `docs/migrate-kitchen-issue-cost.sql`) ก่อนรัน หน้ารายงานซ่อนคอลัมน์ต้นทุนและขึ้นว่าต้องอัปเดต office-server

## คงเหลือคำนวณยังไง

หน้าวัตถุดิบคงเหลือไม่ได้อ่านตัวเลข "คงเหลือ" จากที่ไหน — คำนวณสดทุกครั้ง:

```
คงเหลือ = ยอดนับล่าสุด (stock_count ของสาขาครัวกลาง)
        + รับเข้าหลังวันนับ (kitchen_material_receipt + store_receiving)
        - เบิกไปใช้หลังวันนับ (kitchen_material_issue)
        + ผลิตได้หลังวันนับ (kitchen_production_run)
```

ตัวตั้งคือการนับจริง ไม่ใช่ยอดสะสมตั้งแต่ต้น การนับสต๊อกรอบใหม่จึงล้างความคลาดเคลื่อน
ที่สะสมมาให้เองโดยอัตโนมัติ

เส้นแบ่งคือ *หลังวันที่นับ* ไม่ใช่ *หลังเวลาที่นับ* เพราะใบรับของกับใบเบิกวัตถุดิบเก็บแค่วันที่
ไม่มีเวลา รายการที่เกิดในวันเดียวกับที่นับจึงไม่ถูกรวม — ถูกต้องถ้านับตอนปิดร้าน
และเป็นกติกาเดียวกับที่หน้าสต๊อกสาขาใช้อยู่

สินค้าที่ยังไม่เคยถูกนับที่ครัวกลางเลย จะรวมรับเข้า/เบิกใช้ทั้งหมดตั้งแต่ต้น หน้าเว็บขึ้นคำเตือน
ให้เห็นชัดว่ารายการไหนอยู่ในสภาพนี้

## คำสั่งผลิตมาจากไหน

คอลัมน์ `source` เก็บที่มาไว้เสมอ เพราะเวลาตัวเลขดูแปลก คำถามแรกคือ "ใครสั่ง"

| source | ป้ายในหน้าเว็บ | เกิดจาก |
|---|---|---|
| `manual` | กรอกเอง | ครัวกลางเลือกสินค้าและใส่จำนวนในหน้ารายการ |
| `demand` | ยอดสาขา | รวมยอดที่สาขาสั่งเบิกในหน้านับสต๊อก (ดูหัวข้อถัดไป) |
| `plan` | ตามแผน | สร้างจากแผนรายวัน `kitchen_production_plan_day` ในหน้าแพลนผลิต |

กันใบซ้ำ กดปุ่มสร้างซ้ำวันเดิมจึงปลอดภัย — `demand` ด้วย unique index `UX_kitchen_order_day_auto`
(produce_date, product_key, source) · `plan` ด้วย `UX_kitchen_order_plan_day` (หนึ่งแผนต่อหนึ่งใบ):

- **สร้างจากยอดสาขา** อัปเดตจำนวนของใบเดิม (ยอดเบิกยังขยับได้จนกว่าจะปิดรอบ)
- **สร้างจากแผน** ข้ามใบที่มีอยู่แล้ว ไม่ทับ (ครัวอาจแก้จำนวนไปแล้ว) · ใบเดิมที่ถูกยกเลิกนำกลับมาใช้ด้วยจำนวนตามแผน

คำสั่งแบบกรอกเอง (`manual` — หน้าสั่งผลิต และปุ่ม "สั่งผลิต" รายตัวในหน้ารายการที่สาขาเบิก) ไม่อยู่ใน index นั้น
**กดสั่งแต่ละครั้งได้ใบแยกกัน** แม้เป็นสินค้าเดิมวันเดิม ตารางในหน้าสถานะการผลิตแสดงเวลาที่กดสั่ง (`created_at`)
ใต้วันที่ผลิต และเรียงใบที่เพิ่งสั่งขึ้นก่อนในวันเดียวกัน

ฐานที่สร้างก่อนหน้านี้มีข้อจำกัดเดิม `UQ_kitchen_order_day` ครอบทุก source (manual ได้ใบเดียวต่อสินค้าต่อวัน)
ต้องเปลี่ยนเป็น index ใหม่บนเครื่องที่ออฟฟิศหนึ่งครั้ง — ไม่ต้องรู้รหัส sa:
คลิกขวา `office-server\update-office-server.bat` ของ repo **Narai-branch** → Run as administrator
(ดึงโค้ด → รันไฟล์ใน `office-server\sql\` ด้วย login จาก `.env` → รีสตาร์ต service · ไฟล์ที่รันคือ
`kitchen-001-order-per-click.sql` เนื้อเดียวกับ `docs/migrate-kitchen-order-per-click.sql` ของที่นี่)

คนที่มีรหัส sa จะรันไฟล์ที่นี่เองก็ได้ (รันซ้ำได้):

```
sqlcmd -S localhost\SQLEXPRESS -d InventoryNarai -U sa -P '<รหัสผ่าน>' -I -b -i docs\migrate-kitchen-order-per-click.sql
```

ระหว่างที่ยังไม่ได้รัน `createManualOrder` (`src/services/kitchenService.js`) ลองสร้างใบใหม่ก่อน ชนข้อจำกัดเดิม
ค่อยถอยไปถามว่าจะเพิ่มจำนวนเข้าใบเดิมไหม (ใบเดิมที่ยกเลิกไปแล้ว = ถามว่าจะนำกลับมาใช้) ตอบไม่ = ไม่บันทึกอะไร
รันสคริปต์แล้วไม่ต้องแก้อะไรที่หน้าเว็บ ใบใหม่จะแยกเองทันที

## หน้ารายการที่สาขาเบิก

หน้ารายการที่สาขาเบิกแสดงของที่สาขาสั่งเบิก ตามช่วงวันส่งที่เลือก (ค่าเริ่มต้น วันนี้–พรุ่งนี้)
รวมยอดต่อสินค้า กดที่ชื่อเพื่อดูรายสาขา/เลขใบ กด "สั่งผลิต" รายตัว หรือ "สร้างคำสั่งผลิตทั้งหมด"

- **แหล่งข้อมูล:** `myfbdata.orderd` บน MySQL ของ POS ตารางเดียวกับที่ปุ่ม "สั่งของ" ในหน้านับสต๊อก
  ของ Narai-branch เขียน (`api/insert_order.js`, `Ord_ReqType = 'TRF'`) ครัวจึงเห็นยอดตั้งแต่สาขากดส่ง
  ไม่ต้องรอสโตร์ดึงใบไปจัด (เดิมปุ่ม "สร้างจากยอดสาขา" อ่าน `store_fulfillment` ซึ่งมีของหลังสโตร์ดึงใบแล้ว
  และแสดงเฉพาะสินค้าที่มีสูตร — ตอนนี้ใช้แหล่งเดียวกับแผงนี้ ไม่ต้องมีสูตรก่อน)
- **เฉพาะของที่ครัวกลางผลิต:** สินค้าที่ชื่อ (ในใบเบิก หรือชื่อในทะเบียนสินค้า POS ถ้าใบไม่มีชื่อ) ขึ้นต้นด้วย "FC"
  ไม่สนตัวพิมพ์เล็กใหญ่ — กติกาเดียวกับรายการเมนูในหน้าสั่งผลิต อยู่ที่ `isKitchenItemName` ใน `lib/kitchenRequests.js`
  (เดิมกรองด้วยรหัส 7 หลักขึ้นต้น 10 / 010)
- **ใบที่ยกเลิก ("ยกใบเบิก") ไม่นับ** — ถ้าโหลดรายการใบยกเลิกไม่ขึ้น แผงจะเตือนว่ายอดอาจรวมใบที่ยกเลิกแล้ว
- หน่วยต่างกันของสินค้าเดียวกันแยกเป็นคนละแถว (บวกกันไม่ได้)
- route: `GET /api/kitchen_branch_requests?from=&to=` ใน `server.js` (ช่วงไม่เกิน 31 วัน)

## แพลนผลิต

ปฏิทินรายเดือนกว้างเต็มหน้า ช่องวันแสดง **ชื่อเมนู + จำนวน** (ไม่แสดงรหัส · ฟ้า = ยังไม่สั่งผลิต,
เขียว = สั่งผลิตแล้ว · จอมือถือแสดงเป็นจุด) รายละเอียดของวันเปิดเป็น **ป๊อปอัพ**: ชื่อ หมวด จำนวนสูตร
เลขใบสั่งผลิต + สถานะ หมายเหตุ เวลาที่บันทึก (กดพื้นหลังหรือ Esc เพื่อปิด)

- **เลือกวันเดียว** — กดช่องเปิดป๊อปอัพแผนของวัน เพิ่ม/แก้/ลบ · ปุ่ม + มุมช่องเปิดป๊อปอัพพร้อมฟอร์มเพิ่มแผน ·
  ปุ่มเหลือง **"สั่งผลิต"** ในแต่ละแถวออกคำสั่งผลิตของแผนนั้นรายการเดียว (`createOrderFromPlanDay`) ·
  ปุ่ม "สร้างคำสั่งผลิตจากแผนวันนี้" ท้ายป๊อปอัพออกให้ทุกแผนของวันที่ยังไม่สั่ง
- **เลือกหลายวัน** — กดทีละวัน · Shift+คลิกเลือกเป็นช่วง · กดหัวคอลัมน์ (เช่น "จ.") เลือกทุกวันนั้นในเดือน
  แล้วกด "ตั้งแผนให้วันที่เลือก" เปิดป๊อปอัพ (ระบุช่วงวันที่เพิ่มได้ในนั้น) ตั้งเมนูเดียวกันให้ทุกวันที่เลือกทีเดียว

เมนูที่เลือกได้คือเมนู QC/RD ที่ชื่อขึ้นต้นด้วย "FC" (กติกาเดียวกับหน้าสั่งผลิต)

**ปุ่ม "เช็คสูตร"** ในแต่ละแผนของป๊อปอัพวัน — ดูวัตถุดิบตามสูตร QC/RD (`/api/qcrd_recipe`) คูณจำนวนสูตรของแผน
ทั้งหน่วยสูตรและหน่วยสต๊อก (÷ converter) เทียบคงเหลือครัว (`getKitchenBalance`) ไม่พอ = สีแดง · ดูอย่างเดียว
บรรทัด "ไม่ตัด BOM" แสดงจาง ๆ · ยังเปลี่ยนเป็นวัตถุดิบทดแทนรายแผนไม่ได้ (ต้องมีที่เก็บฝั่ง office-server)

**เพิ่มหลายเมนูแล้วบันทึกทีเดียว** — ในฟอร์มเพิ่มแผน (ทั้งวันเดียวและหลายวัน) กด "เพิ่มลงรายการ แล้วเลือกเมนูถัดไป"
เมนูจะไปต่อในรายการด้านบนของฟอร์ม (ถังขยะ = เอาออก) แล้วกด "บันทึกแผน N รายการ" ครั้งเดียว ·
เมนูที่เลือกค้างในฟอร์มแต่ยังไม่กดเพิ่มถูกบันทึกไปด้วย · หน้าเว็บเรียก `saveDatedPlans` ทีละเมนู
ถ้าพลาดกลางทาง รายการที่บันทึกแล้วหลุดออกจากรายการ กดบันทึกซ้ำจึงไม่เกิดแผนซ้ำ

**กรอกเป็นจำนวนสูตร (ส่วน)** แล้วหน้าเว็บคำนวณยอดผลิตให้ = จำนวนสูตร × "จำนวนที่ผลิตได้" ของสูตร QC/RD หนึ่งชุด
เช่น ไก่นิว 1 สูตร = 88 กก. ใส่ 2 → 176 กก. · ใส่ทศนิยมได้ (0.5 สูตร) สูตรที่ยังไม่มีข้อมูลที่ผลิตได้
นับ 1 สูตร = 1 หน่วย "สูตร" ตารางแผนเก็บแค่ยอดรวม (`planned_qty`) จำนวนสูตรหารกลับจากผลผลิตต่อสูตรตอนแสดง/แก้
คำสั่งผลิตที่สร้างจากแผนใช้ยอดนี้ตรง ๆ แล้วฟอร์มผลิตหารกลับเป็นจำนวนสูตรเอง วัตถุดิบจึงคูณตามจำนวนสูตรที่วางไว้
(เดิมตอนสร้างคำสั่ง หน้าเว็บรีเซ็ตยอดกลับเป็น 1 สูตรตามสูตรล่าสุด — เลิกทำแล้ว เพราะจะทับจำนวนสูตรที่วางแผนไว้)

ตาราง `kitchen_production_plan_day` หนึ่งแถวต่องาน — **ตั้งเมนูเดิมซ้ำในวันเดิม = งานใหม่อีกแถว ไม่ทับของเดิม**
(ฟอร์มขึ้นเตือนว่ามีแผนเมนูนี้อยู่แล้วกี่วัน กันกดซ้ำโดยไม่ตั้งใจ) แต่ละแผนสั่งผลิตได้แยกใบ
แผนผูกกับคำสั่งผลิตด้วย `kitchen_production_order.plan_day_id` (เพิ่มด้วย `docs/migrate-kitchen-plan-day-multi.sql`
= `office-server/sql/kitchen-004-plan-day-multi.sql` ซึ่งลบ `UQ_kitchen_plan_day` และเติม `plan_day_id`
ให้ใบ `plan` เดิมด้วยวัน+สินค้า) แผนที่ออกคำสั่งไปแล้ว (ใบยังไม่ถูกยกเลิก) ลบไม่ได้ แต่ **แก้จำนวนสูตรได้จนกว่าคำสั่งจะ "ผลิตเสร็จ"** — `saveDatedPlans` ของ office-server ปรับ `order_qty` ของคำสั่งตามใน transaction เดียวกัน (วัตถุดิบที่เบิกไปแล้วไม่เปลี่ยน เบิกเพิ่มที่ดินสอของสถานะการผลิต)

action ของ office-server: `getDatedPlans` · `saveDatedPlans` · `deleteDatedPlan` · `createOrdersFromPlan` · `createOrderFromPlanDay`
(ตัวหลังสุดเพิ่มทีหลัง — office-server ที่ยังไม่อัปเดตจะตอบ "ไม่รู้จักคำสั่ง" หน้าเว็บบอกให้รัน update-office-server.bat)

แผนประจำรอบเดิม (`kitchen_production_plan` รายวัน/รายสัปดาห์) เลิกใช้แล้ว — ปุ่ม "แผนประจำรอบ" /
"สร้างจากแผน" ในหน้ารายการสั่งผลิตเดิม (ตอนนี้คือรายการที่สาขาเบิก) ถูกเอาออก ตารางกับ action เดิมยังอยู่ (ข้อมูลไม่หาย และย้อนกลับได้)
แต่ `createOrdersFromPlan` อ่านแค่แผนรายวันแล้ว

**เปิดใช้บนฐานที่มีอยู่แล้ว:** คลิกขวา `office-server\update-office-server.bat` ของ repo **Narai-branch**
→ Run as administrator — ดึงโค้ด office-server ใหม่ สร้างตารางด้วย `office-server/sql/kitchen-002-plan-by-date.sql`
(ตัวเดียวกับ `docs/migrate-kitchen-plan-by-date.sql`) แล้วรีสตาร์ต service ในครั้งเดียว
ก่อนรัน หน้าแพลนผลิตจะขึ้นว่า "ยังไม่มีตารางแผนผลิตรายวัน — รัน update-office-server.bat"

## ขั้นตอนเปิดใช้

1. **รันสคีมา** บนเครื่องที่ออฟฟิศ

   ```
   sqlcmd -S localhost\SQLEXPRESS -d InventoryNarai -U sa -P '<รหัสผ่าน>' -I -b -i docs\schema-kitchen-sqlserver.sql
   ```

   หรือเปิดใน SSMS แล้วกด Execute — ได้ 8 ตาราง: `kitchen_recipe`, `kitchen_recipe_item`,
   `kitchen_production_plan`, `kitchen_production_plan_day`, `kitchen_production_order`, `kitchen_production_run`,
   `kitchen_material_issue`, `kitchen_material_receipt`

2. **ตั้งรหัสสาขาของครัวกลาง** ใน `.env` ของ office-server แล้วรีสตาร์ต `NaraiUsageAPI`

   ```
   KITCHEN_BRANCH=<รหัสสาขาครัวกลาง>
   ```

   ตอนนี้ครัวกลางยังไม่ใช่สาขาในระบบ ค่านี้จึงยังไม่มีข้อมูลให้จับคู่ ตั้งเป็น `kitchen` ไว้ก่อนได้
   มันมีผลแค่สองคอลัมน์ในหน้าคงเหลือ คือ "นับล่าสุด" (จาก `stock_count`) กับส่วนของ "รับเข้า"
   ที่มาจาก `store_receiving` — ซึ่งทั้งคู่จะเป็น 0 จนกว่าครัวจะถูกเพิ่มเป็นสาขาจริงและเริ่มนับสต๊อก
   ระหว่างนี้คงเหลือคิดจากใบรับเข้าของครัวเองล้วนๆ ซึ่งถูกต้องอยู่แล้ว

3. **deploy office-server** — `git pull` ที่ `D:\Narai-branch-main` แล้วรีสตาร์ตเซอร์วิส

4. **deploy storefct** บน Vercel (merge เข้า main แล้ว Vercel build ให้เอง)

5. **สร้างสูตรก่อนใช้งานจริง** — หน้าอื่นงอกจากสูตรทั้งหมด:
   ปุ่ม "สร้างจากยอดสาขา" แสดงเฉพาะสินค้าที่มีสูตร · ปุ่ม "คำนวณวัตถุดิบตามสูตร"
   ในหน้าเบิกวัตถุดิบต้องมีสูตร · หน้าวัตถุดิบคงเหลือแสดงเฉพาะของที่อยู่ในสูตรหรือเคยถูกเบิก

## ล็อกอินและสิทธิ์

ทำแล้ว — ดู `docs/auth.md` · ทุก action ของ `/api/kitchen` ผ่าน `authMiddleware` ก่อน
อ่าน = ดูหน้าครัวได้อย่างน้อยหนึ่งหน้า · คำสั่งเขียนผูกกับหน้าที่ใช้คำสั่งนั้น (`KITCHEN_WRITE` ใน `lib/pages.js`
เช่น `saveDatedPlans` = แก้ไขได้ในแพลนผลิต) **เพิ่ม action ใหม่ใน `lib/kitchenDb.js` ต้องเพิ่มลง `KITCHEN_WRITE` ใน `lib/pages.js` ด้วย**
ไม่งั้นผู้ใช้ทั่วไปได้ 403 · หน้าที่ได้สิทธิ์ดูอย่างเดียว ปุ่มที่ติด `data-write` ถูกซ่อน

ช่อง **ผู้บันทึก**: ล็อกอินแล้ว server ใส่ชื่อผู้ใช้ลง `recorder` ให้ (ถ้าหน้าเว็บไม่ได้ส่งมาเอง —
`actorName` ใน `lib/auth.js`) ยังไม่ล็อกอิน (ยังไม่ตั้ง `AUTH_REQUIRED`) ลงเป็น `ครัวกลาง` เหมือนเดิม

- **ของที่ผลิตเสร็จยังไม่เข้าสต๊อกอัตโนมัติ** ในแง่ของหน้าสต๊อกสาขา — `kitchen_production_run`
  ถูกนับรวมในหน้าวัตถุดิบคงเหลือของครัวกลางแล้ว แต่ยังไม่ได้เขียนกลับไปที่ `stock_count`
  ซึ่งเป็นตารางของ "การนับ" ไม่ใช่ "ยอดคงเหลือ" การเขียนผลผลิตลงไปจะทำให้ประวัติการนับปนกับ
  สิ่งที่ไม่ได้นับ ถ้าต้องการให้เชื่อมกันจริงควรทำเป็นตารางความเคลื่อนไหวแยก ไม่ใช่ยัดลงตารางนับ
- **ครัวกลางยังไม่ใช่สาขาในระบบ** จึงไม่มีใบเบิกของตัวเอง ไม่ถูกนับรวมในหน้ารวมสต๊อกทุกสาขา
  และนับสต๊อกผ่านแอปสาขาไม่ได้จนกว่าจะมีบัญชีผู้ใช้ที่ผูกกับรหัสครัว ถ้าต้องการให้ครบวงจรจริง
  ต้องเพิ่มครัวเป็น outlet ในระบบ POS (เป็นของผู้ขาย เราเพิ่มเองไม่ได้) แล้วเติมลง `lib/branches.js`
- **ยังไม่มีการเช็คว่าเบิกเกินคงเหลือ** — เบิกได้เลย แล้วหน้าคงเหลือจะโชว์ติดลบเป็นสีแดง
  ตั้งใจให้เป็นแบบนี้ก่อน เพราะยอดคงเหลือช่วงแรกยังไม่แม่นจนกว่าจะนับสต๊อกครบรอบ
  ถ้าบล็อกตั้งแต่ต้นจะกลายเป็นว่าเบิกของจริงไม่ได้เพราะตัวเลขในระบบผิด
