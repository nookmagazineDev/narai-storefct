# ล็อกอิน + สิทธิ์รายหน้า

ทุกคนต้องมีบัญชีของ storefct เอง (แยกจากบัญชีเว็บสาขา `hr_user`) แอดมินกำหนดได้ว่าแต่ละคนใช้หน้าไหนได้
และแต่ละหน้า **ดูอย่างเดียว** หรือ **แก้ไขได้**

| ส่วน | ไฟล์ |
|---|---|
| รายชื่อหน้า + สิทธิ์ที่ API แต่ละตัวต้องการ | `lib/pages.js` (ใช้ทั้งหน้าเว็บและ server) |
| ออก/ตรวจ token, route `/api/auth/*` | `lib/auth.js` |
| ผู้ใช้/รหัสผ่าน/สิทธิ์ (SQL) | `office-server/storefct-auth.js` + `office-server/sql/storefct-001-users.sql` ของ Narai-branch |
| หน้าเว็บ | `src/pages/Login.jsx`, `src/pages/admin/Users.jsx`, `src/components/auth/PageGate.jsx`, `src/contexts/AuthContext.jsx` |

## ทำงานยังไง

```
หน้าล็อกอิน -> POST /api/auth/login -> office-server storefctLogin (ตรวจรหัส scrypt ใน InventoryNarai)
            <- คุกกี้ sf_auth (HttpOnly, เซ็นด้วย AUTH_SECRET, อายุ 7 วัน)
ทุก /api/*  -> authMiddleware: ตรวจลายเซ็น -> ตรวจสิทธิ์ตาม lib/pages.js -> 401 / 403 / ผ่าน
```

- **ปลอม token ไม่ได้** — แก้สิทธิ์ในคุกกี้เองแล้วลายเซ็นไม่ตรง = 401
- **สิทธิ์อัปเดต**: เปิดหน้าเว็บใหม่ดึงสิทธิ์ล่าสุดทันที (`/api/auth/me`) และระหว่างใช้งาน server ต่ออายุสิทธิ์จาก office-server ทุก 10 นาที
  ปิดบัญชี = ใช้ต่อไม่ได้ภายใน 10 นาที · ถ้าออฟฟิศติดต่อไม่ได้ตอนต่ออายุ ใช้สิทธิ์เดิมไปก่อน (ไม่เด้งทุกคนออก)
- **ดูอย่างเดียว**: หน้านั้นมีแถบฟ้าบอก ปุ่มบันทึก/ส่ง/ลบ (ติด `data-write`) ถูกซ่อน และ server ตอบ 403 "ดูได้อย่างเดียว" ถ้าเรียกตรง
- **แอดมิน** ใช้ได้ทุกหน้า + เมนู "จัดการผู้ใช้" · ถอดแอดมิน/ปิดบัญชีของตัวเองไม่ได้ และต้องเหลือแอดมินอย่างน้อยหนึ่งคนเสมอ
- **ชื่อผู้บันทึก**: ล็อกอินแล้ว คำสั่งครัวกลางใส่ชื่อผู้ใช้เป็นผู้บันทึกให้ และปุ่มอนุมัติยอดรับเขียนชื่อคนกดแทนคำว่า "โกดัง"

## สิทธิ์ของ API (สรุปจาก `lib/pages.js`)

- อ่านข้อมูลคลัง (`/api/pending_orders` ฯลฯ) = ดูหน้าคลังได้อย่างน้อยหนึ่งหน้า
- จัดของ / ดึงข้อมูล / อนุมัติยอดรับ = แก้ไขได้ในหน้า ปฏิทินใบเบิก, จัดของ หรือ ตรวจสอบสถานะ
- อ่านข้อมูลครัว = ดูหน้าครัวได้อย่างน้อยหนึ่งหน้า
- คำสั่งเขียนของครัว ผูกกับหน้าที่ใช้คำสั่งนั้น เช่น `saveDatedPlans` = แก้ไขได้ในแพลนผลิต, `saveKitchenCount` = แก้ไขได้ในวัตถุดิบคงเหลือ
- API ที่ไม่มีในตาราง = แอดมินเท่านั้น — **เพิ่ม route ใหม่ใน server.js ต้องเพิ่มกติกาใน `ROUTE_RULES` ด้วย** ไม่งั้นผู้ใช้ทั่วไปได้ 403

## เปิดใช้ (ครั้งแรก)

1. merge PR ของ Narai-branch แล้วรัน `office-server\update-office-server.bat` — สร้างตาราง + บัญชี `admin`
2. ตั้ง env บน Vercel: `AUTH_SECRET` (สุ่มยาว ๆ ดู `.env.example`) แล้ว merge PR นี้ / redeploy
   ตอนนี้ยังไม่บังคับล็อกอิน ทุกคนใช้ได้เหมือนเดิม
3. เข้า `/login` ด้วยชื่อ `admin` — **รหัสที่กรอกครั้งแรกจะกลายเป็นรหัสของ admin** (6 ตัวขึ้นไป)
4. เมนู "จัดการผู้ใช้" → เพิ่มผู้ใช้ ติ๊กสิทธิ์ (มีชุดสำเร็จ โกดัง / หัวหน้าครัว / พนักงานครัว / ดูอย่างเดียว)
5. ตั้ง `AUTH_REQUIRED=1` บน Vercel แล้ว redeploy — ทุกคนต้องล็อกอิน

ลืมรหัส admin: ใน SSMS `UPDATE dbo.storefct_user SET password_hash = NULL WHERE username = N'admin'`
แล้วล็อกอินใหม่ รหัสแรกที่กรอกจะเป็นรหัสใหม่
