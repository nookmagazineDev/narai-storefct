# ข้อมูลนับสต๊อก — ดึงจาก SQL Server ผ่าน office-server

## ทำไมต้องอ้อม

ข้อมูลนับสต๊อกอยู่บน **SQL Server** `InventoryNarai` ที่ออฟฟิศ ซึ่งเปิดพอร์ต 1433 ให้เฉพาะ IP
ในไทย ฟังก์ชันบน Vercel วิ่งมาจากต่างประเทศจึงต่อตรงไม่ได้ ส่วนเครื่องที่ออฟฟิศต่อผ่าน
`localhost` ได้อยู่แล้ว และ Vercel เรียกเครื่องนั้นที่พอร์ต 8787 ได้อยู่แล้ว

```
เบราว์เซอร์ → /api/stock_count_summary (แอปนี้) → office-server :8787/schedule → SQL Server
```

เส้นทางเดียวกับที่ [Narai-branch](https://github.com/nookmagazineDev/Narai-branch) ใช้อยู่ทุกวัน
(`api/stockcount.js` ของฝั่งนั้น) — เราแค่มาเป็นผู้เรียกอีกราย ไม่ได้ตั้งอะไรใหม่

## ทำไมถึงเปลี่ยน

เดิมหน้า "รวมสต๊อกทุกสาขา" อ่านชีท `ข้อมูลนับสตอค` แต่ชีทนั้น**ตายแล้ว** — `saveStock` ฝั่ง
Narai-branch เขียนไว้ตรง ๆ ใน `office-server/stock.js` ว่า *"เขียนลง SQL อย่างเดียว ไม่เขียนชีท
อีกแล้ว"* ชีทจึงไม่มีแถวใหม่เข้าอีก และหน้านี้เสิร์ฟภาพนิ่งเก่าอยู่เงียบ ๆ โดยไม่มีอะไรฟ้อง

## ใช้ action อะไร

`getStockTotal` — ตัวเดียวกับที่หน้า "รวมสต๊อกทุกสาขา" ของ Narai-branch ใช้

เลือกตัวนี้แทนที่จะดึงแถวดิบมาคำนวณเองเพราะกติกามันไม่ตรงไปตรงมา: ต้องเอา**ยอดนับล่าสุดของแต่ละ
(สินค้า, สาขา)** แล้วสาขาไหนยังไม่เคยนับให้ถอยไปใช้**ยอดยกมา** (`dbo.stock_balance`) แทน ถ้าต่าง
คนต่างคำนวณ สองแอปจะโชว์ตัวเลขไม่ตรงกันเมื่อกติกาฝั่งโน้นเปลี่ยน

สิ่งที่แอปนี้ทำเองเหลือแค่สองอย่าง เพราะ office-server เข้าถึงไม่ได้

- **ราคา** จาก `myfbdata.item` (`Itm_LastPrice` → `Itm_AvePrice`) บน MySQL
- **หมวดหมู่** จากชีท Col N ที่ทีมงานยังกรอกมืออยู่ — `storeCat` ที่ SQL ส่งมาเป็นภาพนิ่งตอนย้าย
  ข้อมูล จึงใช้เป็นตัวสำรองเมื่อ Col N ไม่รู้จักรหัสนั้น

## ตั้งค่า

| ตัวแปร | ค่าเริ่มต้น | หมายเหตุ |
|---|---|---|
| `USAGE_API_BASE` | `https://usage.khanoykorshabu.com` | ตัวเดียวกับค่าเริ่มต้นของ Narai-branch (Cloudflare Tunnel) — ส่วนใหญ่ไม่ต้องตั้ง ถ้าตั้งค่าเก่า (`storenarai.dyndns.tv:8787`) ค้างไว้ ทุกหน้าที่ใช้ office-server จะได้ HTTP 404 |
| `USAGE_API_TOKEN` | (ว่าง) | ต้องตรงกับ `API_TOKEN` ที่ตั้งไว้ฝั่ง office-server — ถ้าฝั่งนั้นไม่ได้ตั้ง ก็เว้นว่าง |

ตั้งบน Vercel ที่ Project Settings → Environment Variables แล้ว redeploy

**ไม่ต้องไปแก้อะไรที่เครื่อง SQL Server** — `getStockTotal` เป็น action ที่ office-server เปิด
ให้อยู่แล้ว (อยู่ใน `READ_ONLY` ของ `api/schedule.js` ฝั่งโน้น) และตาราง `stock_count` /
`stock_balance` มีข้อมูลอยู่แล้ว สิ่งเดียวที่ต้องเช็คคือ ถ้าฝั่งนั้นตั้ง `API_TOKEN` ไว้
ต้องเอาค่าเดียวกันมาใส่ `USAGE_API_TOKEN` ของแอปนี้

## เวลามีปัญหา

แคชรีเฟรชทุก 15 นาที ถ้าโหลดไม่สำเร็จ**ตั้งแต่ครั้งแรก** endpoint จะตอบ HTTP 503 พร้อมสาเหตุ
เป็นภาษาไทย แทนที่จะคืนรายการว่างซึ่งดูเหมือน "ของหมดคลัง"

| ข้อความ | แปลว่า |
|---|---|
| เครื่อง IT-Narai อาจปิดอยู่ หรือ NaraiUsageAPI ไม่ได้รันอยู่ | `ECONNREFUSED` — เปิดเครื่อง แล้ว `Restart-Service NaraiUsageAPI` |
| dyndns อาจยังไม่อัปเดต IP ใหม่ | `ENOTFOUND` — IP ออฟฟิศเปลี่ยนแต่ dyndns ยังตามไม่ทัน |
| ต้องตั้ง USAGE_API_TOKEN ให้ตรงกับ API_TOKEN | ฝั่งนั้นเปิดตรวจ token แล้วแต่ฝั่งนี้ยังไม่ได้ตั้ง |
| ไม่ตอบกลับภายในเวลาที่กำหนด | เน็ตออฟฟิศช้า หรือเครื่องกำลังอุ่น cache อยู่ |

ถ้าเคยโหลดสำเร็จมาก่อนแล้วรอบถัดไปพัง จะยังเสิร์ฟของเดิมต่อ (ดีกว่าหน้าว่าง) และ log เหตุผลไว้

รายละเอียดการกู้เครื่องที่ออฟฟิศอยู่ใน `docs/troubleshooting-server.md` ของ repo Narai-branch

## สิ่งที่ยังไม่ได้ทดสอบ

เขียนในสภาพแวดล้อมที่ต่อ office-server จริงไม่ได้ ผ่านเฉพาะ `node --check` และ unit test
ที่จำลองคำตอบ: การส่ง action/`_user`/token, การไม่ลองใหม่เมื่อปลายทางตอบว่าไม่สำเร็จ, การลองใหม่
เมื่อเจอ 5xx, ข้อความไทยของแต่ละสาเหตุ และการ map คำตอบ (รหัสมี 0 นำหน้า, สาขาตัวใหญ่-ตัวเล็ก,
ราคาถอยไป `Itm_AvePrice`, หมวดหมู่ถอยไป `storeCat`, ตัดไอเทมที่ไม่มีใครนับทิ้ง)

**ยังไม่เคยเรียก office-server จริง** — หลัง deploy กรุณาเปิดหน้า "รวมสต๊อกทุกสาขา" แล้วเทียบ
ตัวเลขกับหน้าเดียวกันในแอป Narai-branch ว่าตรงกัน
