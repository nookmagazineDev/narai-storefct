# ย้ายงานสโตร์จาก Google Sheets ไป SQL Server

เอกสารนี้คู่กับ [schema-store-sqlserver.sql](schema-store-sqlserver.sql) และ [office-server.md](office-server.md)

## ทำไม

สถานะการทำงานของโกดัง (จัดของ / รับของ / ดึงข้อมูลใบเบิก / ยกเลิกใบเบิก) เคยอยู่ใน Google Sheet
แล้วอ่านกลับผ่าน gviz ซึ่งมีปัญหาสะสม

1. **ช้า** — ทุกครั้งที่เปิดหน้า ต้องดึงทั้งแท็บมา parse แล้วยุบ "แถวหลังสุดชนะ" ใน memory
2. **ข้อมูลไม่สด** — แคช 15 นาที
3. **เขียนแล้วไม่รู้ผล** — Apps Script ถูกยิงแบบ fire-and-forget เขียนไม่ติดก็ไม่มีใครรู้
4. **ต้องมีสะพานซิงก์ถาวร** — แท็บ `รับของ` เขียนโดยแอป Narai-branch ซึ่งย้ายไป SQL Server
   ไปแล้ว ถ้า storefct ไปอยู่ MySQL จะต้องคอยซิงก์ชีทตามตลอดไป

ข้อ 4 คือเหตุผลหลักที่เลือก SQL Server แทน MySQL — **สองแอปอ่านเขียนตารางเดียวกันตรงๆ
ไม่ต้องมีตัวกลางอีกเลย** และตารางสินค้า (`stock_item`) ก็อยู่ฐานเดียวกันอยู่แล้ว

## ข้อแลกที่ยอมรับแล้ว

Vercel ต่อ SQL Server ตรงไม่ได้ (ไฟร์วอลล์เปิดพอร์ต 1433 ให้เฉพาะ IP ในไทย) ทุกอย่างจึงผ่าน
office-server ที่พอร์ต 8787

| | เดิม | ตอนนี้ |
|---|---|---|
| ดูรายการใบเบิก | MySQL ตรง | MySQL ตรง (`orderd` เป็นของ POS ย้ายไม่ได้) |
| **บันทึกจัดของ** | Google Sheet | **ต้องผ่านเครื่องที่ออฟฟิศ** |
| กดดึงข้อมูล | Sheet + ไฟล์ | **ต้องผ่านเครื่องที่ออฟฟิศ** |
| ซิงก์ `รับของ` | ต้องมีสะพานถาวร | **ไม่ต้องมีเลย** |

**ถ้าเครื่องที่ออฟฟิศดับ โกดังจะเปิดดูใบเบิกได้ แต่บันทึกจัดของไม่ได้** — ยืนยันรับข้อแลกนี้แล้ว
วิธีกู้เครื่องอยู่ใน `docs/troubleshooting-server.md` ของ repo Narai-branch

## ขั้นตอนเปิดใช้ — ต้องทำตามลำดับ

สวิตช์คือ `STORE_SOURCE` ค่าเริ่มต้น `sheet` **ห้ามตั้งเป็น `sql` ก่อนทำครบข้อ 1-3**
ไม่งั้นหน้าเว็บจะพังทันที เพราะ office-server ยังไม่รู้จัก action พวกนี้

### 1. สร้างตาราง (บนเครื่องที่ออฟฟิศ)

```
sqlcmd -S localhost\SQLEXPRESS -d InventoryNarai -U sa -P '<รหัสผ่าน>' -i docs\schema-store-sqlserver.sql
```

### 2. อัปเดต office-server

โค้ดฝั่งนั้นอยู่คนละ repo (Narai-branch) — ใช้แพตช์ที่ให้ไว้

```powershell
cd <โฟลเดอร์โค้ด>
git am < 0001-add-store-work-actions.patch
npm install ; Restart-Service NaraiUsageAPI
```

เช็คว่าขึ้นแล้ว: `Invoke-RestMethod http://localhost:8787/health`

### 3. ย้ายข้อมูลเก่าจากชีท

รันจากเครื่องไหนก็ได้ที่เรียก office-server และเปิด Google Sheets ได้

```bash
node scripts/import-store-sql.mjs --dry-run   # ดูจำนวนก่อน ไม่ส่งอะไร
node scripts/import-store-sql.mjs             # ส่งจริง (รันซ้ำได้ MERGE ตามคีย์)
```

**⚠️ เทียบจำนวน "อ่านจากชีท" กับที่เห็นในชีทจริงทุกครั้ง** — gviz คืนเฉพาะแถวที่ผ่าน "ตัวกรอง"
ที่เปิดค้างไว้ โดยไม่ฟ้องอะไรเลย ทีม Narai-branch เจอของจริงตอนย้าย `ข้อมูลนับสตอค`: gviz ให้มา
6,112 แถว จากของจริง 70,785 แถว ถ้าน้อยกว่าให้รันใหม่ด้วย `--csv`

```bash
node scripts/import-store-sql.mjs --csv --gid-fetched=<เลข> --gid-cancelled=<เลข>
```

สองแท็บหลังถูกสร้างโดย Apps Script ตอนใช้งาน จึงไม่รู้ gid ล่วงหน้า ต้องเปิดแท็บนั้นในเบราว์เซอร์
แล้วคัดเลขท้าย URL มาเอง

แท็บ `ดึงข้อมูลใบเบิก` มีข้อจำกัดเพิ่ม: คีย์ฝั่ง SQL คือ `(outlet_id, ord_no)` แต่ชีทไม่เก็บ
`outlet_id` สคริปต์จึงต้องไปหาจาก `myfbdata.orderd` ให้ — ใบที่จับคู่สาขาไม่ได้จะถูกข้ามและ
รายงานจำนวนกลับมา ไม่ได้เดาให้

### 4. สลับสวิตช์

ตั้ง `STORE_SOURCE=sql` บน Vercel (Project Settings → Environment Variables) แล้ว redeploy

ตอนบูต เซิร์ฟเวอร์จะบอกเองว่าอ่านเขียนที่ไหน

```
📝 งานสโตร์อ่าน/เขียนที่ SQL Server ผ่าน http://storenarai.dyndns.tv:8787
```

## ถอยกลับ

ตั้ง `STORE_SOURCE=sheet` แล้ว redeploy — ทางชีททั้งหมดยังอยู่ครบ ไม่ได้ลบทิ้ง
ข้อมูลที่เขียนลง SQL ระหว่างนั้นจะไม่ตามกลับมาที่ชีท ต้องกรอกเองถ้าจำเป็น

## ยังไม่ได้ทำ

- **แอป Narai-branch ยังเขียนชีท `รับของ` อยู่** จนกว่าฝั่งนั้นจะย้ายมาเขียน
  `dbo.store_receiving` แทน จะต้องรัน `import-store-sql.mjs รับของ` เป็นระยะเพื่อตามเก็บ
  — นั่นคืองานที่ทำให้สะพานซิงก์หายไปจริงๆ และเป็นขั้นต่อไป
- **`ยกเลิกใบเบิก`** ยังไม่มีแอปไหนเขียนลงตาราง ต้องซิงก์จากชีทเหมือนกัน

## สิ่งที่ยังไม่ได้ทดสอบ

เขียนในสภาพแวดล้อมที่ต่อ SQL Server, office-server และ Google Sheets ไม่ได้เลย ผ่านเฉพาะ
`node --check` ทุกไฟล์ และ unit test ที่จำลองคำตอบของ office-server: รูปร่าง payload ที่ส่งไป
ทุก action, การยุบรหัสซ้ำ, การ normalize รหัส/วันที่, และการที่ผลลัพธ์ฝั่งอ่านมีชื่อฟิลด์ตรงกับ
ที่หน้าเว็บอ่านอยู่เดิมเป๊ะ

**ยังไม่เคยรันจริง**: คำสั่ง T-SQL ในไฟล์สคีมา, MERGE ทุกตัว, และการย้ายข้อมูล
ทำข้อ 1-3 บนเครื่องจริงแล้วดูผลก่อนสลับสวิตช์
